## 1. PROJECT SUMMARY

| Item | Detail |
| --- | --- |
| What it is | A hotel room-status and cleaning-management web app. Staff mark rooms check-in / check-out / clean-start / clean-finished / ready, managers assign recurring template tasks to cleaners per day, cleaners upload a start photo and finish video, and platform staff provision and manage tenant organizations and users. |
| Who it is for | Three audiences: **platform_admin** (Mercury FM staff, manages organizations), **org_admin / admin** (hotel managers, manage rooms, tasks, users), and **cleaner** (performs daily tasks with photo/video evidence). |
| Primary sources | `README.md:1-314`, `src/App.jsx:25-65`, `docs/platform.sql:1-592`, `api/` handlers. |
| Current state | **Core application is working and deployed** (SPA + Vercel serverless API + Supabase). Recent security fixes are applied and build passes. Several operational items remain open: 3 user-management RPCs are still missing in the hosted DB, the Supabase DB password in local config is rejected, email delivery/login-flow confirmations are pending, and there are no automated tests. See §13. |
| Maturity signals | Manual QA checklist exists (`docs/MANUAL_TEST_CHECKLIST.md:1-66`); security audit exists (`docs/security-audit.md:1-91`); no CI, lint, typecheck, or test runner (`package.json:6-30`). |

### RLS, triggers, seed, migrations

- **RLS policies**: `public.organizations`, `public.profiles` (plus `repair_platform_permissions.sql`), `email_verification_codes` (enabled, service-only), and all tenant tables. `task_fields` is staff-only; `daily_task_field_values` allows staff full access and cleaners to select/update values on their own assignments. Helper functions `is_platform_admin()`, `in_org()`, `is_org_staff()` gate tenant policies; NIC is never directly selectable by `authenticated`.
- **Trigger**: `trg_sync_room_status` AFTER INSERT on `org_<slug>.room_status_history` executes `<schema>.sync_room_status()` (`platform.sql:443-444`). No views exist.
- **Seed data**: `seed.sql:1-13` inserts legacy unqualified branches/rooms; incompatible with current schema and not referenced by `supabase/config.toml:76` (which expects `supabase/seed.sql`, absent). First `platform_admin` is created manually per `README.md:107-110`; verified with `verify_platform_owner.sql:1-3`. Tenant backfill happens in `ensure_tenant_members()` (`platform.sql:101-111`).
- **Migration status**: `docs/platform.sql` = current baseline for new projects; `supabase/apply-tenant-rpcs.sql` = upgrade for existing project; `user-management-rpcs.sql`, `email-verification.sql`, `fix-list-organization-users.sql`, `fix-room-status-created-by-fk.sql`, `task-fields-and-start-times.sql` = patches (the last one is idempotent and loops every `org_<slug>` schema); `tenant-users-migration.sql`, `members-followup.sql`, `updated-provision-organization.sql`, `docs/schema.sql`, `add_profile_nic.sql`, `seed.sql` = historical/superseded; `grant-tenant-service-role.sql` = deprecated stub; `reset_database.sql` = destructive manual utility. ## 9. KEY FLOWS

### Flow A — Cleaner self-signup → verification → login → password change

1. `src/pages/SignupPage.jsx:19-44` validates org slug, NIC, email; `apiPost('/start-signup', {...})`.
2. `api/start-signup.js:45-98` resolves active org by slug, creates the auth user with `password = NIC`, inserts `public.profiles` (`role: 'cleaner'`, `email_verified:false`) and calls RPC `insert_tenant_user` with `p_must_change_password:true`; on failure it deletes the auth user (`:119-126`).
3. `api/start-signup.js:100-104` calls `issueCode()`; `api/lib/emailVerification.js:189-216` stores only `code_hash` in `email_verification_codes` (or memory fallback) and sends SMTP email.
4. `SignupPage.jsx:45-54` navigates to `/verify-email` with `codeSent`/`delivered` state; `src/components/VerifyEmail.jsx:55-113` posts `/send-code` and `/verify-code`; `verifyCode()` (`emailVerification.js:247-291`) checks expiry/attempts/hash, deletes the code, and sets `email_verified`.
5. `src/pages/VerifyEmailPage.jsx:13-34` calls `refreshProfile()` and routes to `/login`, `/change-password`, or role home.
6. `src/pages/LoginPage.jsx:39-109` signs in, verifies org/profile, signs out unverified users; `ProtectedRoute.jsx:29-31` forces `/change-password`; `ChangePasswordPage.jsx:27-50` updates auth password, calls `mark_password_changed`, refreshes profile, routes via `homeForRole()` (`src/lib/authFlow.js:75-79`).

### Flow B — Admin updates a room status

1. `src/pages/RoomStatusPage.jsx:42-72` loads tenant `branches` and `rooms` via `db()` (`src/lib/db.js:19-22`).
2. `openUpdate()` (`:83-92`) restricts editing to `org_admin`/`admin`; modal writes `status`, `status_time`, `created_by: profile.id` (`:115-122`).
3. Insert into `org_<slug>.room_status_history` via browser PostgREST; RLS policy `hist_write` requires `is_org_staff(slug)` (`docs/platform.sql:528`).
4. Trigger `trg_sync_room_status` updates `rooms.current_status/status_time/updated_at` (`:435-444`).
5. `loadRooms()` re-reads rooms; history modal reads `room_status_history` ordered by `created_at` (`:133-157`).
6. `created_by` FK was repointed from `members(id)` to `public.profiles(id) ON DELETE SET NULL` by `supabase/fix-room-status-created-by-fk.sql:41-46` (org_admin lives only in `profiles`).

### Flow C — Cleaner uploads start photo / finish video

1. `src/pages/CleanerTasksPage.jsx:36-70` loads today's `daily_assignments` → `daily_tasks` → `task_runs`.
2. `handleFile()` (`:89-130`) compresses photos (`src/lib/media.js:6-33`) / validates videos (`:35-74`).
3. `uploadDatabaseMedia()` (`src/lib/media.js:118-142`): POST `/api/media/start` with bearer token; each 3 MB chunk is base64-encoded and retried 3 times (`:105-116`); POST `/api/media/complete`.
4. `api/media/start.js:51-90` verifies tenant caller + cleaner role + task ownership, inserts `media` row; `api/media/chunk.js:40-65` locks the row, checks ownership/index, upserts `media_chunks`; `api/media/complete.js:35-62` validates chunk count and total bytes, sets `complete=true`.
5. `saveAction()` (`CleanerTasksPage.jsx:132-192`) inserts/updates `task_runs` with `start_photo_id` / `finish_video_id`.
6. `src/pages/CleanerHistoryPage.jsx:9-53` (`MediaLink`) fetches `/api/media/<id>` with token, creates a blob URL, and revokes it on unmount; `api/media/[id].js:30-98` checks staff/owner access and streams with `Range`, `nosniff`, and sandbox CSP.

### Flow D — Platform admin provisions an organization

1. `src/pages/PlatformPage.jsx:119-161` validates slug/fields and POSTs `/api/create-organization` with bearer token.
2. `api/create-organization.js:31-53` verifies `platform_admin`; `:76-83` calls RPC `provision_organization(p_name, p_slug)`.
3. `docs/platform.sql:386-561` inserts `organizations`, creates `org_<slug>`, 11 tables, trigger, tenant functions, RLS policies, grants, calls `ensure_tenant_members` + `refresh_exposed_schemas`.
4. `api/create-organization.js:87-106` creates the org_admin auth user and inserts `public.profiles` with `role:'org_admin'`, `must_change_password:true` (no tenant member by design, `:108-109`).
5. On failure, rollback deletes the auth user and drops the schema, profiles and org row via direct `pg` (`:116-135`, `api/lib/dbPool.js:18-25`).
6. `PlatformPage.jsx:163-192` can deactivate/reactivate via `/api/set-organization-active`, which calls `refresh_exposed_schemas()` so PostgREST stops exposing that schema (`api/set-organization-active.js:38-53`).

### Flow E — Org admin manages users

1. `src/pages/UsersPage.jsx:24-40` calls `supabase.rpc('tenant_users', { p_schema: schemaName })` (staff-only RPC; one of the few ways NIC is exposed to clients).
2. Create: `:61-88` POST `/create-user` → `api/create-user.js:53-96` creates auth user, profile, tenant member.
3. Role change / reset / delete: `:101-118` POST `/manage-user` → `api/manage-user.js:65-156` checks caller role and org scope, calls the three user-management RPCs and/or `auth.admin.updateUserById` / `deleteUser`.
4. These RPCs are still reported missing in the hosted DB, so role edit / NIC reset paths currently fail until `supabase/user-management-rpcs.sql` is run (`docs/security-audit.md:77`).

### Operational / pending

TLS verification was confirmed to work with the bundled CA.
